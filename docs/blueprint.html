모든 문서는 요청·승인·완료 시각과 처리자를 이력으로 남깁니다. 결재는 기본적으로 금액과 상관없이 전체 결재선을 거치고, 총괄 관리자가 매장·금액별로 줄이거나 승인자를 지정할 수 있습니다.

금액·결산

가격과 부가세

  • 적용 단가 = 매장별 단가(없으면 본사 기준가) − 매장별 할인
  • 요청 시점의 단가·할인·세액을 문서에 고정 저장
  • 세액 = 공급가 × 10% (라인별, 원 단위 절사)
  • 면세 품목은 세액란에 0 (면세)
  • 표시: 계정 지정값 → 없으면 매장 기본값 (별도/포함)

결산 (판매 수익 기준, 월)

순매출총매출 − 할인 − 환불 (VAT 제외)
매출원가기초재고 + 매입 − 기말재고
판관비인건비 + 임대 + 공과금 + 내부사용 + 운영비 + 손실·결손 + 감가상각
영업이익순매출 − 매출원가 − 판관비
결산액영업이익 − 로열티 ± 영업외

로열티·본사 정산서

  • 매장별 정책: 매출 %, 정액, 혼합, 구간
  • 기준 기본값 VAT 제외 순매출, VAT 포함으로 변경 가능
  • 월 정산서 = 로열티 + 본사가 대신 결제한 외부 구매액
  • 입금: 매장이 등록 → 본사 확인 (부분·완납·연체)

사용·결손 구분

  • 내부사용: 포장·일회용품·위생·사무용품 소진 → 소모품비
  • 식기: 파손 시 손실(사유 '식기 파손'), 기준 단가(기본 10만원) 이상 고가 식기는 비품 → 감가상각, 파손 시 비품 폐기(처분손실)
  • 공과금: 전기·수도·가스·통신 → 수도광열비·통신비
  • 결손: 실사 차이, 배송 부족, 시음, 샘플, 직원 음료
  • 손실: 유통기한, 파손, 품질 불량

구현 현황

1~11단계를 모두 구현했고, 계정별 권한과 업무 흐름 자동 점검 61개 항목이 통과했습니다(식기·포장 구분 포함). 테스트 환경은 docker-compose 소형 구성(포트 18080)입니다. 계정별 확인 순서는 저장소 docs/TEST-SCENARIOS.md 에 있습니다.
