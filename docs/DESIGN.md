## 2차 사용자 점검 반영 (v0.6, 2026-11-20)

| 영역 | 변경 |
|---|---|
| 공통 | 모든 표 머리글을 눌러 정렬(오름·내림, 새로고침 후에도 유지). 필수 항목(*)이 비면 저장을 막고 "필수 항목을 입력하세요: …"로 항목 이름 표시. 알림 창은 다른 화면으로 가거나 바깥을 누르면 닫힘 |
| 권한 | 총괄 관리자·슈퍼바이저는 물류 관리자·인사 관리자 권한을 함께 가짐(같은 범위). 슈퍼바이저 활성화, 총괄 바로 아래 등급(물류·인사는 그 아래). 매장 관리자는 직원 급여 중 아르바이트 시급만 봄 |
| 이름 | 총괄 관리자 `장총괄` (가상) |
| 조직도 | 총괄은 상단 선택이 "전체(합산)"로 고정 |
| 직원·급여 전체 | 총괄 전체 화면: 모든 사이트 직원 + 직원 미등록 계정 / 급여 전체: 사이트별 총액 + 모든 직원별 급여 |
| 연봉 테이블 | 1단계 금액 + 상승률(%, 복리) 또는 증가액으로 20단계 자동 작성(직원 월급 갱신). 프리랜서 f1~f20 = 월 100만원 단위, 3.3%만 공제 |
| 근무표 | 주간 / 4주. 직원이 휴무를 먼저 지정 → 자동 로테이션(오픈 → 마감 → 최번시 일반, 인원 부족 시 오픈·마감 우선, 주 소정 시간·사용률 기준 순환). 매장 근무 기준(오픈·마감 시각, 최번시, 최소 인원). 긴급 연차 → 대체 인원 후보·배정. 퇴사자 근무 표시 → 오늘부터 다시 배치. 수동 조정·삭제·연차는 승인 메모 필수, 조정 이력. 본사는 평일 9 to 6 |
| 근무 마감 | 모든 직원이 근무를 마치며 판매·결제 금액 입력(결제 합계 = 판매 합계 확인) → 그날 소계 → 점주·매장 관리자가 일 매출로 반영 |
| 물류 | 모든 승인 후 "물류 추적" 화면에서 구매·발송·도착·수령 검수까지 추적, 끝나면 물류 담당이 확인 완료(CLOSED) |
| 결산 | 주 마감(월~일, 일요일 24시 자동, 분개를 잠그지 않는 주간 확정 실적). 본사 매출 = 로열티 합계 + 물류 이득(매장 공급가 − 본사 출고 원가) |
| 투자자 | 투자 항목마다 자금 출처(본사 지원 / 투자자 출자·투자자 지정). 이익금 배분 비율 = 투자자 출자 ÷ (투자자 출자 + 본사 지원). 인사 메뉴 "투자자 지급": 월 결산액 × 비율 → 지급액 결정 → 지급 완료, 투자자 화면에 지급 내역 |
| 오류 수정 | 비용 구분 '영업외' 저장 시 DataIntegrity 오류 (구분 값 길이) |

데모 데이터(가상): 슈퍼바이저 본사 직원, 매장별 아르바이트 보강, 4주 자동 근무표, 강남 임차보증금 = 투자자A 출자.

| 권역 | 기본 17개 시·도(특별시·광역시·특별자치시·도). 매장 관리에서 하위 권역 추가·삭제 |
| 연봉 테이블 | 직급군 × 20단계 (사원 s, 매장 관리자 m, 인사 관리자 h, 물류 관리자 l, 슈퍼바이저 v, 총괄 a). 등급 지정 시 연봉·월 급여(÷12) 표시, 급여 계산에 사용. 직급군 추가 가능 |
| 직원 | 사번 `00000001`부터 8자리 연번. 주 소정 기본 40시간. 기타 비과세 항목(이름·금액) 여러 개 |
| 급여 | 상여금(과세)·퇴직금(4대보험·근로소득세 제외, 추정치 제안) 입력. 매장별 화면에 사이트 이름 명확히, **전체**는 상신 없이 사이트별 지급 총액 표 |
| 근무 | 첫 화면(홈)에서 모든 직원 출근·퇴근. 매장별 주간 **근무표**(편집: 인사·점주·매장 관리자, 조회: 사원), 지난주 복사 |
| 품목 | 품목 코드 자동 생성(카테고리 접두어-4자리, 제안값 수정 가능, 접두어 규칙 편집). **본사 매입가**(물류 관리자 이상만) 와 마진 |
| 재고 | **본사 창고 재고**: 본사 입고, 매장 발송 시 자동 차감 |
| 물류 | 요청 기한(요청자) + 처리 기한(물류 담당), 목록·보드 기한 지남 표시. 수령 검수에서 부족·파손·불량 → **재발송**(무상 재발송 요청 자동 생성) 또는 **손실·결손 처리**(결재 초안). 외부 구매 입력칸 겹침 수정 |
| 선택 메뉴 | 상단 매장 선택을 바꾸면 화면이 그 매장 기준으로 다시 그려짐. 화면 안의 선택 목록(계정 연결, 투자자 후보, 품목 단가 매장 등)은 해당 지점 값만 |
| 분석 | **매출 추이**(최근 12개월 vs 1년 전 같은 달 겹친 그래프). 매장 비교: 점주 매장 3개 이하 = 내 매장 + 상/하위 1곳, 4개 이상 = 내 매장 평균 vs 상/하위 (다른 매장 이름 비공개) |
| 조직도 | 매장 라인: 본사 + 자기 매장 + 다른 매장의 매장 관리자만. 투자자: 본사 + 투자 매장 |
| 투자자 | 설계도 메뉴 숨김. 투자 매장 월별 매출액·이익 그래프(1년). 투자금 = 투자자 출자 + 본사 지원 (구분·합계) |
| 설명 | 모든 메뉴에 설명(메뉴 툴팁 + 화면 상단 안내, [사용법] 펼침) |

데모 데이터 보강: 센트럴 베이커리(`baker1`), 본사 직원 연봉 등급, 본사 창고 기초 재고, 매출 추이용 과거 23개월 일 매출(결산 미반영 "과거 실적").

## 0. 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 백엔드 | Java 21 + Spring Boot 3 (Spring Security, JPA/QueryDSL, Flyway) |
| 프론트엔드 | **TypeScript + React 계열로 통일** (v0.3, Flutter에서 변경) |
| 관리자 웹 / 물류 페이지 | React 18 + Vite + TanStack Query/Table |
| 모바일·태블릿 앱 | React Native (Expo) — iOS/Android, 카메라·바코드·푸시(FCM/APNs) |
| 코드 공유 | pnpm 모노레포 `packages/shared` — API 클라이언트·타입·권한·금액/VAT 계산·i18n 을 웹/앱이 공동 사용 |
| 화면 우선순위 | **태블릿·노트북 우선**, 모바일은 하단 탭으로 조회·확인·승인·요청 (§11.0) |
| 매출 데이터 | 1차: 수기 입력 + 엑셀 업로드 → 2차: POS 연동(어댑터 구조로 선반영) |

| 투자자 | `투자자` 읽기 전용 등급 추가 |

| 본사 정산서 | 월 발행 + 매장 입금 확인(부분/완납/연체) (§8.5) |
| 점주 급여 열람 | 매장별 설정(총괄): 허용 시 개인별, 미허용 시 총액만 |
| 세무 연계 | 회계 프로그램 내보내기(더존 등) + 전자세금계산서 발행·수취 연동 (§8.6) |
| 면세 | 세액란에 `0 (면세)` 표시 |

| 외부 구매 | 결제 주체 매장 또는 본사 선택, 비용은 항상 해당 매장 귀속 |
| 물류 결재 | 기본 = 금액 무관 전체 결재선, 총괄이 금액 기준·승인자 지정 가능 |

| DB | PostgreSQL 16, Primary + Sync Standby 2중화 (K8s: CloudNativePG) |

### 2.1 등급과 계층

```
                    총괄 관리자 (HQ_ADMIN)
                   /                    \
          [본사 라인]                     [매장 라인]
  물류 관리자 (LOGISTICS_MGR)            점주 (OWNER)
  인사 관리자 (HR_MGR)  ← 물류관리자와 동급
  슈퍼바이저 (SUPERVISOR) ← 권역 담당, 정의만 하고 비활성(is_active=false)
                                           |
                                    매장 관리자 (STORE_MGR)
                                           |
                                    일반 사원 (STAFF)

  투자자 (INVESTOR) — 계층 밖, 읽기 전용
```

- 한 사람이 여러 매장에 다른 등급으로 배정될 수 있음 (예: A점 점주 + B점 매장관리자).
- "상위 그룹" = 매장 라인에서는 바로 위 등급, 물류 요청의 경우 물류관리자, 인사·급여 요청의 경우 인사관리자, 최종은 총괄.
- 슈퍼바이저: 등급 코드·권역 스코프만 만들어 두고 비활성. 활성화 시 권역 내 매장 조회·결재 단계로 쓸 수 있도록 결재선 승인자 유형에 미리 포함.
- 인사관리자: 담당 매장의 직원 등록, 계약, 근무기록, 급여 계산·확정, 급여명세 발행 담당. 매장 회계·물류 내역은 조회 불가.

## 4. 아키텍처

### 4.1 서비스 구성 (MSA)

| 서비스 | 책임 | DB |
|---|---|---|
| **gateway** | Spring Cloud Gateway, JWT 검증, 라우팅, Rate limit | — |
| **auth-service** ★독립 | 계정, 등급, 매장 배정, 로그인/토큰(Spring Authorization Server), VAT 표시 오버라이드, 감사로그 | `auth_db` (독립 클러스터) |
| **store-service** | 매장, 사업자·VAT 기본값, 임대 계약, 매장 생성 마법사 | `core_db.store` |
| **catalog-service** | 카테고리, 품목, 본사 기본 물류, 매장별 단가·할인 | `core_db.catalog` |
| **logistics-service** | 물류 요청, 물류 승인, 발송, 수령, 외부 구매 | `core_db.logistics` |
| **inventory-service** | 재고 원장, 실사, 손실/결손/사용 | `core_db.inventory` |
| **approval-service** | 범용 결재 엔진(결재선 템플릿, 단계, 메모, 위임) | `core_db.approval` |
| **sales-service** | 매출 수기/엑셀, POS 어댑터(2차) | `core_db.sales` |
| **hr-service** | 직원, 근무기록, 급여 계산, 급여명세 | `core_db.hr` (개인정보 컬럼 암호화) |
| **settlement-service** ★독립 | 분개 원장, 월 결산, 비용(임대·사용·기타), 투자금, 투자자 공개 | `settlement_db` (독립 클러스터) |
| **report-service** | 1장 리포트 스냅샷 생성, 등급별 렌더, PDF | `core_db.report` + 오브젝트 스토리지 |
| **notification-service** | FCM 푸시, 이메일, 앱 내 알림 | `core_db.notify` |

- 서비스 간 동기 호출: REST(OpenFeign). 비동기: **Transactional Outbox + Kafka(Strimzi)**.
- settlement-service 는 다른 서비스 DB를 직접 읽지 않고 **이벤트만 수신**해 자체 원장을 구성 → 결산 데이터 독립성 확보.

주요 이벤트:

| 이벤트 | 발행 | 구독 |
|---|---|---|
| `LogisticsReceived` | logistics | inventory(입고), settlement(매입 분개) |
| `StockAdjustmentApproved` (손실/결손/사용) | inventory | settlement(감모·폐기 분개) |
| `DailySalesClosed` | sales | settlement(매출 분개), inventory(레시피 차감, 2차) |
| `PayrollConfirmed` | hr | settlement(급여·4대보험 분개) |
| `ApprovalCompleted/Rejected` | approval | 원 문서 서비스, notification |
| `StoreCreated` | store | catalog(기본 단가 복제), approval(기본 결재선), settlement(계정 초기화) |

### 4.2 Kubernetes 구성

```
Ingress (NGINX) + cert-manager
  └ gateway ─┬ auth-service
             ├ store / catalog / logistics / inventory / approval
             ├ sales / hr / report / notification
             └ settlement-service
Kafka (Strimzi, 3 broker)   Redis (세션·캐시)   MinIO/S3 (첨부·PDF·백업)
PostgreSQL (CloudNativePG): auth-pg, settlement-pg, core-pg  — 각 1 primary + 1 sync standby
Observability: Prometheus + Grafana, Loki, OpenTelemetry/Tempo
배포: Helm chart + Argo CD, 네임스페이스 espresso-dev / espresso-prod
```

### 4.3 소형 구성 (WAS 모드)

매장 수가 적거나(예: 10개 이하) K8s 운영 부담이 클 때:

- **3개 배포 단위**: `auth` / `settlement` / `core`(나머지 모듈을 한 JAR로 묶은 Modular Monolith).
- Kafka 대신 Outbox 테이블 폴링 → 서비스 간 HTTP 전달.
- 현재 규모(약 10개 매장)는 이 구성으로 시작 → §4.4 기준에 따라 서비스 분리.
- 코드는 처음부터 **모듈 경계(Gradle 멀티모듈 + 패키지 의존 규칙, ArchUnit 검사)** 로 작성해 MSA로 분리 가능하게 유지.
- VM 2대 + PostgreSQL Streaming Replication(Patroni) 또는 K8s 소형 클러스터 어느 쪽에도 동일 이미지 배포.

### 4.4 확장 계획 (10 → 1,000개 매장)

| 단계 | 매장 수 | 구성 |
|---|---|---|
| S | ~50 | 3개 배포 단위(auth / settlement / core), K8s 위 HPA, Outbox 폴링 |
| M | ~300 | core 에서 logistics·inventory·report 분리, Kafka 도입, Redis 캐시 |
| L | ~1,000 | 전 서비스 분리, DB 읽기 복제본 추가, 대용량 테이블 월 파티션, 리포트·결산 비동기 배치 워커 |

1,000개 매장 기준 추정 (가정: 매장당 월 물류 30건×20라인, 일 매출 마감 1건, 직원 10명)
- 물류 라인 월 60만 건, 재고 원장 월 약 200만 건, 분개 월 약 100만 행 → PostgreSQL 단일 클러스터로 수용 가능, 단 원장·이력 테이블은 **월 단위 파티션**.
- 월말 결산·리포트는 매장 단위 작업으로 쪼개 큐에 넣고 워커 수평 확장 (1,000건 병렬 처리).
- 비교 화면: 1,000개를 한 화면에 나열하지 않고 **권역 → 매장** 드릴다운, 상·하위 N개, 지표별 정렬·필터, 집계 테이블(일/월 요약) 사전 계산.
- 확장 시 데이터 이전 없이 진행되도록 처음부터: 모든 테이블에 `store_id`, 서비스별 스키마·DB 계정 분리, ID는 UUIDv7(시간순).

  - 비품 기준 단가: 카테고리별 `asset_threshold`(기본 식기 100,000원, 총괄이 [품목·단가 › 비품 기준]에서 변경). 기준가가 이 금액 이상이면 `is_asset` → 재고가 아니라 비품(206)으로 입고, 5년 정액 감가상각.

## 6. 핵심 업무 흐름

### 6.1 물류 요청 (요구 1, 2, 6, 19, 22)

요청 라인 2종:

| source_type | 입력 | 비고 |
|---|---|---|
| `HQ` 본사 기본 물류 | 카탈로그에서 선택 + 수량 | 매장별 단가·할인 자동 적용(스냅샷 저장) |
| `EXTERNAL` 외부 구매 | **URL**, 품명, 판매처, 단가, 수량, 배송비, 카테고리, **결제 주체(매장/본사)**, 증빙 | 단가는 VAT 포함/별도 선택 입력 → 내부적으로 공급가/세액 분리 |

외부 구매 결제 주체와 회계 처리 — **비용은 항상 해당 매장 귀속**:

| 결제 주체 | 처리 |
|---|---|
| 매장 | 매장이 직접 결제·증빙 첨부 → 매장 매입/비용으로 즉시 반영 |
| 본사 | 본사가 결제(대납) → 매장 매입/비용으로 반영 + 본사에 대한 **미지급금(본사 청구액)** 발생 → 본사-매장 정산서에서 상계 |

상태 흐름:

```
DRAFT ─상신→ REQUESTED ─(매장 결재선: 필요시 점주/총괄)→ STORE_APPROVED
   → LOGISTICS_APPROVED(물류관리자 승인·단가 확정) → PREPARING → SHIPPED(송장번호)
   → DELIVERED → RECEIVED(매장 검수: 라인별 수령수량) → COMPLETED
분기: REJECTED(반려 사유) / CANCELLED / PARTIALLY_RECEIVED → 차이분 자동으로 '배송 결손' 초안 생성
외부 구매: LOGISTICS_APPROVED → PURCHASED(구매 증빙 첨부) → 이후 동일
```

### 6.2 재고

- 원장 방식: `stock_ledger(store_id, item_id, qty_delta, unit_cost, reason, ref_type, ref_id, occurred_at)`.
- 사유: 입고/판매차감(2차)/손실/결손/사용/실사조정/매장간 이동.
- 평가: **이동평균법**(제안) — 월말 기말재고 금액 = Σ 수량 × 이동평균단가.
- 실사: 앱에서 바코드/목록 기반 실사 → 차이분이 결손 요청 초안으로 생성.

### 6.3 결손·손실 처리 (요구 10)

1. 앱에서 등록: 품목, 수량, 유형(손실 / 결손 / 내부사용), 사유코드(결손: 실사차이·배송부족·**시음**·샘플·직원음료 / 손실: 유통기한·파손·불량), **사진 첨부**, 메모.
2. 금액 자동 산출(수량 × 이동평균단가).
3. 결재선 결정 → 순차 승인: **매장관리자 → 점주 → 총괄** (기본).
4. 최종 승인 시 재고 차감 + `StockAdjustmentApproved` 이벤트 → 결산 반영.
5. 반려 시 재고 영향 없음, 반려 사유 기록.

### 6.4 범용 결재 엔진 (요구 10, 19)

- 모든 요청 화면 하단 공통 **메모·결재란**: 결재선 표시, 단계별 상태/시각/의견, 댓글 스레드, 첨부.
- `approval_line_template(doc_type, store_id?, min_amount?, max_amount?, steps[])` — 총괄이 매장별·금액 구간별로 결재선과 **지정 승인자** 설정.
- **기본값 = 전체 결재**: 금액 구간 템플릿이 없으면 문서 종류의 전체 결재선을 모두 거침.
  - 물류 요청: (요청자 상위) 매장관리자 → 점주 → 물류관리자 → 총괄
  - 결손/손실/내부사용: 매장관리자 → 점주 → 총괄
  - 급여 확정: 인사관리자 → 점주(열람 미허용 매장은 총액만 보고 결재) → 총괄
  - 요청자 본인 단계는 자동 통과(예: 점주가 요청하면 점주 단계 생략).
- 총괄이 금액 기준(예: 10만원 미만은 물류관리자만)을 만들면 그 구간은 축약 결재선 적용.
- 단계 승인자 지정 방식: 등급(`ROLE:OWNER`) 또는 특정 사용자(`USER:{id}`).
- 기능: 상위 그룹 상신, 반려(사유 필수), 회수(첫 승인 전), 부재 시 위임(기간), 총괄 직권 승인(사유·감사로그).

### 6.5 시간값 (요구 22)

- 모든 문서 헤더: `requested_at`, `approved_at`, `completed_at`, `created_at`, `updated_at` (`timestamptz`, UTC 저장 / KST 표시).
- 모든 상태 전이는 `*_status_history(doc_id, from, to, actor_id, memo, occurred_at)` 에 append-only 기록 → 화면에 타임라인으로 표시.

## 7. 가격·할인·부가세

### 7.1 매장별 단가·할인 (요구 7)

```
item.base_price (본사 기준 공급가)
store_price(store_id, item_id, unit_price?, discount_type[RATE|AMOUNT]?, discount_value?, valid_from, valid_to)
적용 단가 = (store_price.unit_price ?? item.base_price) − 할인
```
- 요청 시점 단가·할인·세액을 라인에 **스냅샷** 저장 → 이후 단가 변경이 과거 문서에 영향 없음.
- 매장 그룹 단가(예: 직영/가맹)도 필요하면 `price_group` 으로 확장.

### 7.2 부가세 (요구 8)

- 저장: 모든 금액은 `supply_amount`(공급가액), `vat_amount`(세액), `total_amount` 3개 컬럼, 정수 원 단위.
- 세액 계산: 과세 품목 `vat = floor(공급가 × 10%)`, **라인 단위 계산 후 합산**(제안).
- 면세 품목: 세액란에 `0 (면세)` 표시, 포함/별도 모드와 무관하게 공급가 = 합계. 합계 영역에 과세/면세 소계를 따로 표시.
- 표시 모드: `effective_mode = account_override ?? store.vat_display_mode` (`EXCLUSIVE` 별도 / `INCLUSIVE` 포함).
- 포함가 입력(외부 구매 등) 시 역산: `supply = round(total / 1.1)`, `vat = total − supply`.

### 8.2 결산 (요구 11) — 판매 수익 기준

```
순매출        = 총매출(공급가) − 매출할인 − 환불
매출원가      = 기초재고 + 당기매입 − 기말재고
매출총이익    = 순매출 − 매출원가
판관비        = 인건비 + 임대료 + 공과금 + 내부사용 + 운영비 + 재고손실(손실·결손) + 감가상각
영업이익      = 매출총이익 − 판관비
로열티        = 매장별 설정(§8.4)
결산액        = 영업이익 − 로열티 ± 영업외손익
지표          = 원가율, 인건비율, 임대료율, 손실률, 영업이익률, 일평균매출
```
- 월 마감(`period_close`) → 잠금. 마감 후 수정은 조정 분개로만, 총괄 승인 필요.
- 투자금 회수율(누적 결산액 ÷ 투자금)을 투자 화면에 제공.

### 8.3 급여 자동 계산 (요구 25)

- 직원별 계약: 고용형태(정규/계약/아르바이트/사업소득 3.3%), 시급 또는 월급, 소정근로시간, 주휴 대상 여부, 식대 등 비과세 항목.
- 근무기록: 앱 출퇴근 또는 수기, 연장·야간(22~06시)·휴일 가산 1.5배.
- 공제: 국민연금, 건강보험, 장기요양, 고용보험, 근로소득세(간이세액표), 지방소득세 / 3.3%.
- 사업자 부담분: 4대보험 회사분, 산재보험 → 복리후생비.
- 퇴직급여 충당금 월할 적립.
- **요율·최저임금·간이세액표는 연도별 테이블**로 관리(총괄이 매년 갱신).
- 급여 확정 시 `PayrollConfirmed` → 결산 반영, 직원 앱에 급여명세서 발행.

### 11.0 화면 원칙 — 태블릿·노트북 우선

### 11.1 관리자 웹 (React)
- 세부 화면 목록·와이어프레임은 `docs/SCREENS.md`.
- 대시보드(매장 선택기) · 물류(요청/승인/발송/외부구매) · 재고(현황/실사/손실·결손) · 매출 · 비용(임대·사용) · 급여 · 결산 · 리포트 · 결재함
- **매장 비교(총괄)**: 선택한 매장을 열로 나란히(최대 10개), 지표 정규화(원가율·인건비율·손실률·일평균매출), 기간 선택, 순위·편차 하이라이트. 전체 매장은 권역별 집계 → 드릴다운, 지표 순위표(상·하위 N).
- 설정(총괄): 매장·권역, 계정·등급, 카테고리·품목·매장별 단가, 결재선·금액 기준, 계정과목, 로열티, 급여 요율표, VAT 표시 오버라이드, 투자.

### 11.2 모바일·태블릿 앱 (React Native / Expo)
- 물류 요청(카탈로그 / 외부 URL 붙여넣기), 발송 추적, 수령 검수(라인별 수량, 사진)
- 결손·손실·사용 등록(사진), 재고 실사(바코드)
- 결재함(푸시 → 바로 승인/반려), 출퇴근, 급여명세, 매장 선택기

### 11.3 매장 생성 마법사 (요구 27, 총괄 전용)
1. 기본정보(매장명, 주소, 오픈일, 사업자 유형)
2. 부가세 표시 기본값, 결산 기준, **로열티 정책**
3. 임대 계약(보증금, 월세, 관리비, 기간)
4. 설비·인테리어(자산 등록 → 투자금 자동 합산)
5. 기본 물류 패키지 선택(구분별 초도 품목·수량) + 매장별 단가·할인 확인
6. 인원 배정(점주, 매장관리자, 담당 물류관리자·인사관리자, 권역)
7. 결재선(기본 템플릿 복사 후 수정)
8. 검토 → 생성 → 초도 물류 요청 자동 생성

각 단계에 안내 문구·체크리스트 표시, 임시저장 지원.

## 12. 확장성 (요구 18)

- 마스터 데이터(카테고리, 구분, 계정과목, 비용 항목, 결재선, 요율표)는 모두 관리 화면에서 추가/수정.
- 문서 테이블에 `attributes JSONB` 확장 필드 + 총괄이 정의하는 사용자 정의 필드.
- 기능 플래그로 매장별 기능 on/off (예: POS 연동, 출퇴근).

## 13. 데이터베이스 · 2중화 (요구 12)

| 클러스터 | 용도 | 구성 |
|---|---|---|
| `auth-pg` | 계정·권한 | CloudNativePG, primary 1 + sync standby 1 |
| `settlement-pg` | 결산·투자·분개 | 동일 |
| `core-pg` | 나머지 서비스(서비스별 스키마·계정 분리) | 동일 |

- **동기 복제**(synchronous_commit=on, 1 sync standby) → 장애 시 데이터 손실 0, 자동 failover.
- 노드 anti-affinity 로 primary/standby 서로 다른 노드 배치.
- 백업: WAL 아카이빙 + 일 1회 base backup → MinIO/S3 (PITR, 보존 30일 — 확인 필요), 월 1회 복구 리허설.
- 금액: `BIGINT`(원), 수량: `NUMERIC(12,3)`, 시각: `timestamptz`.
- 마이그레이션: Flyway (서비스별).
- 1,000개 매장 대비: 원장·이력·분개 테이블 월 파티션(pg_partman), 조회 전용 복제본 추가 시 리포트·비교 화면은 복제본에서 읽기, 일/월 집계 테이블 사전 계산.
- 소형 구성: VM 2대 Patroni + etcd(또는 단순 streaming replication + 수동 승격).

## 14. 보안 · 감사

- 인증: OAuth2/OIDC(Spring Authorization Server), Access 15분 / Refresh 14일, 앱은 생체인증 잠금 옵션.
- 인가: 등급 + 매장 스코프 이중 체크(게이트웨이 + 서비스).
- 개인정보(주민번호·계좌번호 등 급여 필수 항목): 컬럼 단위 암호화(AES-256, 키는 K8s Secret/외부 KMS), 화면 마스킹, 조회 감사로그.
- 개발·테스트 환경에는 **가명/예시 데이터만** 사용.
- 감사로그: 로그인, 권한 변경, 결재, 금액 수정, 투자·급여 조회 → append-only.
